# Личный кабинет клиента ST96 — экраны, сценарии, состояния

Статус: проект решения. Дата: 2026-11-26.
Связанные: [CABINET-SPEC.md](../CABINET-SPEC.md), [data-api.md](data-api.md), [прототип](prototype.html).

Документ описывает интерфейс: каркас и навигацию, каждый экран (блоки, данные, действия,
состояния, микрокопия), пользовательские сценарии с ветвлениями, уведомления, крайние случаи
и критерии приёмки.

Обозначения: `[поле]` — данные, `{кнопка}` — действие, `«текст»` — микрокопия.
Источник данных — Supabase (`crm.*`), чтение/запись — через `/api/cabinet`.

---

## 1. Каркас и навигация

### 1.1 Шапка сайта

| Состояние | Содержимое |
| --- | --- |
| Гость | Логотип ST96 · Услуги · Поддержка · `{Личный кабинет}` (ведёт на Google-вход) |
| После Google, Telegram не привязан | Логотип · `{Личный кабинет}` · чип «Завершите регистрацию» |
| Клиент | Логотип · Услуги · Поддержка · `{Кабинет}` · чип `N кредитов` · аватар (меню: Профиль, Выйти) |

На мобильном — те же ссылки в бургер-меню; счётчик корзины — точкой на аватаре.

### 1.2 Каркас кабинета

- **Десктоп (≥1024 px):** слева тёмный сайдбар (240 px): логотип, пункты «Дашборд», «Задачи»,
  «Проекты», «Заявки», «Документы», «Корзина» (со счётчиком), внизу «Профиль» и «Выйти».
  Справа — контент с максимумом 1120 px, вертикальный ритм 24/32 px.
- **Планшет/мобильный:** верхняя полоса (логотип, чип кредитов, аватар) + нижнее меню
  «Дашборд · Задачи · Проекты · Документы» и «Ещё» (Заявки, Корзина, Профиль).
- Хлебные крошки на вложенных экранах; заголовок страницы — Unbounded 28–34 px.
- Активный пункт — acid-полоса/заливка, не цветной текст на тёмном.

### 1.3 Защита маршрутов

- Нет сессии → редирект на `/support` (если пришёл с покупки) или модалку Google-входа.
- Сессия есть, `onboarding_status='telegram_required'` → любой `/cabinet/*` редиректит
  на `/cabinet/onboarding`. Исключение — `/cabinet/profile` (можно посмотреть, что привязано).
- `/cabinet/onboarding` при `complete` → редирект на дашборд.
- Ошибка 401 (сессия истекла) → модалка «Сессия истекла, войдите снова».

## 2. Экраны

### 2.1 `/support` — публичная страница «Поддержка» (изменения)

Назначение: продажа пакетов и докупки; единственный вход в покупку для гостя.

Блоки (сверху вниз):
1. Hero услуги поддержки — без изменений.
2. «Пакеты поддержки» — 4 карточки (данные из `/api/packages`: название, цена, кредиты,
   что входит). Кнопка карточки `{Подключить}`.
3. «Докупить кредиты» — 3 бандла + ползунок 100–10 000 (цена 0.30 BYN/кредит); кнопка `{Купить кредиты}`.
4. «Интерпрайс» — `{Обсудить условия}` (форма/Telegram, без корзины).

Поведение кнопок (единое):
- Гость → модалка Google-входа (2.2), выбранный товар запоминается (`sessionStorage` +
  query-параметр возврата) → после входа товар добавляется в корзину → `/cabinet/cart`
  (или онбординг, если Telegram не привязан).
- Клиент → `POST /api/cabinet action=cart_add` → тост «Добавлено в корзину»,
  счётчик +1, кнопка меняется на `{В корзине}` → `/cabinet/cart`.
- Ошибка сети → тост «Не удалось добавить. Попробуйте ещё раз», кнопка не блокируется навсегда.

Состояния: загрузка цен (скелетоны карточек), ошибка загрузки (сообщение + повтор), гость/клиент,
товар уже в корзине.

### 2.2 Google-вход (модалка)

- Заголовок «Вход в личный кабинет», подзаголовок «Один аккаунт для пакетов, задач и документов».
- `{Продолжить с Google}` — `signInWithOAuth`; ниже мелким: «Нажимая, вы соглашаетесь
  с политикой конфиденциальности и обработкой данных».
- Состояния: загрузка (спиннер в кнопке), ошибка OAuth («Не удалось войти через Google. Попробуйте ещё раз»).
- Закрытие крестиком возвращает на /support без потери выбранного товара (он запомнен).

### 2.3 `/cabinet/onboarding` — завершение регистрации

Назначение: создать карточку клиента и привязать Telegram (обязательное условие покупок).

Шаги (прогресс-индикатор 3 шага):
1. **Google** — «Вы вошли как dmitry@example.com» (имя, аватар), статус «Готово».
2. **Telegram** — «Укажите Telegram, чтобы получать правки и уведомления».
   - `{Привязать Telegram}` → `telegram_start` → открывается `t.me/st96_leads_bot?start=cab_…`.
   - Ожидание: «Ожидаем подтверждение в Telegram…» + spinner; опрос каждые 2 с до 90 с.
   - Успех: зелёная строка «Telegram @dmitry_k привязан».
   - Таймаут: «Не получилось? Откройте бота и нажмите Start, затем вернитесь» + `{Обновить}`.
   - Занят другим кабинетом: «Этот Telegram уже привязан к другому кабинету. Напишите в поддержку».
3. **Анкета** — поля: имя (предзаполнено из Google), телефон (маска по стране),
   компания (необязательно), тип «Частное лицо / Юридическое лицо» (по умолчанию частное).
   `{Завершить}` → `profile_save` → `onboarding_status='complete'` → дашборд
   с тостом «Регистрация завершена».

Состояния: шаг недоступен без предыдущего; ошибки полей рядом с полем; сохранение (кнопка со спиннером);
гость на этом маршруте → на /support.

### 2.4 `/cabinet` — дашборд

Блоки:
1. **Приветствие** — «Дмитрий, здравствуйте» + дата; справа чип «Осталось 1 500 кредитов».
2. **Баннеры (по приоритету):**
   - Telegram не привязан — «Завершите регистрацию, чтобы покупать и получать правки» → онбординг.
   - Ожидает оплаты — «Заявка ST-2026-000124 ждёт оплаты до 30.11.2026» → `{Перейти к заявке}`.
   - Пакет истёк — «Пакет истёк 26.11.2026. Продлите, чтобы вносить правки» → `{Продлить}`.
   - Мало кредитов (< 20 %) — «Осталось 180 кредитов. Докупите, чтобы не останавливать правки» → `{Докупить}`.
3. **Карточка пакета** (основная):
   - название пакета, цена периода, даты; крупно «Осталось · 1 500 кредитов» (acid), прогресс-бар
     «740 из 2 240», подпись «до 26.12.2026»;
   - `{Докупить кредиты}` (ведёт на /support#topup или в корзину), `{Сменить пакет}`;
   - строка «Автопродление: включено · за 7 дней до 26.12.2026» + `{Отключить}`; при выключенном —
     «Продлевать вручную» + `{Включить}`; если заявка уже создана — `{Отменить заявку}`;
   - при нескольких проектах — переключатель проекта или список карточек по проектам.
   - **Нет пакета:** карточка заменяется блоком «У вас пока нет пакета» + 4 мини-карточки пакетов
     и `{Выбрать пакет}`; пояснение «Правки и функции расходуют кредиты пакета».
4. **Быстрые метрики** — 3 задачи за период · 2 проекта · 4 документа (ссылки на разделы).
5. **Последние задачи** — 3 строки: дата, задача, статус, «−20 кредитов»; ссылка «Все задачи».
6. **Проекты** — 2 карточки: домен, пакет, остаток, период.
7. **Последние документы** — 3 строки: тип, номер, сумма, дата; ссылка «Все документы».
8. **Пустой кабинет (новый клиент):** приветствие + «Как начать»: выбрать пакет → привязать
   Telegram → написать в бота; иллюстрация без эмодзи.

Состояния: загрузка (скелетоны), ошибка (сообщение + `{Обновить}`), нет пакета, нет задач,
нет проектов, нет документов, есть ожидающая оплата, период истёк.

### 2.5 `/cabinet/tasks` — «Мои задачи»

Назначение: список обращений с потраченными кредитами.

- Заголовок «Мои задачи» + подпись «Списания по пакету за текущий и прошлые периоды».
- Фильтры: проект (все/конкретный), статус (все/в работе/выполнено/ждёт оплаты), период (текущий/все).
- Таблица (десктоп) / карточки (мобильный): дата, задача (первые ~80 символов), проект,
  статус-бейдж, «−N кредитов»; сортировка по дате вниз.
- Статусы и подписи:
  `queued` «В очереди», `running` «В работе», `clarify` «Уточняем детали»,
  `awaiting_confirmation` «Ждёт вашего подтверждения», `ready` «Готово к проверке»,
  `deployed` «Выполнено», `split` «Выполнено частично», `out_of_scope` «Вне пакета»,
  `awaiting_payment` «Ждёт оплаты», `failed` «Ошибка», `thanks` «Спасибо».
- Клик по строке — панель/модалка: полный текст запроса, проект, дата, что сделано (result),
  списано кредитов, статус, кнопка «Написать в поддержку» (бот).
- Пусто: «Задач пока нет. Напишите в бота — агент возьмёт правку в работу» + `{Открыть бота}`.
- Пагинация по 20; данные `support_jobs` по `client_id`.

### 2.6 `/cabinet/projects` — «Мои проекты»

- Карточки: `title` (или `domain`), домен-ссылка, платформа, статус (активен/на паузе),
  пакет, «1 500 из 2 240 кредитов», период, `{Написать в поддержку}`.
- Никаких `workspace_path`, `repo_url`, `deploy_cmd`.
- Пусто: «Проект появится здесь после подключения поддержки» + `{Выбрать пакет}`.
- Если проект без пакета: бейдж «Без пакета» + `{Подключить}`.

### 2.7 `/cabinet/cart` — «Корзина»

- Позиции: тип (Пакет / Кредиты), название, проект (селектор, если проектов ≥2; опция
  «Без проекта (баланс клиента)» — только для чистой докупки, без пакета в корзине; если
  проектов 0 — «Проект подключим после оплаты»), цена, `{Удалить}`. Дубли объединяются.
- Итог: сумма, валюта BYN, сноска «Цены и состав фиксируются в заявке».
- **Плательщик** — две радио-карточки:
  - «Частное лицо» — «Оплата по ссылке, электронный чек в кабинете».
  - «Юридическое лицо» — «Счёт и акт об оказании услуг; оплата по реквизитам».
- При юрлице: название, УНП (9 цифр), юридический адрес, банковские реквизиты; чекбокс
  «Сохранить реквизиты в карточку»; ошибки полей — под полем.
- **Автопродление:** чекбокс «Продлевать пакет автоматически» (для пакета; по умолчанию отмечен),
  подсказка «За 7 дней до конца периода выставим заявку и счёт, отключить можно в кабинете».
- `{Оформить заявку}` (disabled при пустой корзине/без Telegram/без принятия оферты; спиннер при отправке).
- Правовые тексты: ссылка на политику и оферту (оферту согласует владелец).
- Состояния: пусто («Корзина пуста» + `{Перейти к пакетам}`), цена изменилась (баннер
  «Цена обновилась: 560 → 580 BYN», кнопка «Согласен, оформить»), ошибка валидации, нет Telegram
  (баннер + блокировка), превышен лимит открытых заявок.

### 2.8 `/cabinet/checkout` — заказ и статус оплаты (алиас `/cabinet/order/:id`)

- Номер, дата, статус (та же палитра статусов), сумма, плательщик, состав (позиции), проект.
- Таймлайн: «Заявка создана» → «Ожидает оплаты» → «Оплачено» → «Пакет активирован, документы готовы».
- **Физлицо:** `{Перейти к оплате}` (платёжная ссылка), подпись «Электронный чек появится
  в „Документах“ после подтверждения оплаты». Дедлайн: «Оплатите до 30.11.2026, иначе заявка отменится».
- **Юрлицо:** счёт формируется автоматически после оформления; «Готовится» → `{Скачать счёт}`;
  реквизиты для оплаты; после оплаты — «Акт об оказании услуг появится после подтверждения».
- `{Отменить заявку}` (до оплаты, с подтверждением), `{Повторить}` (для отменённой/просроченной —
  возвращает позиции в корзину).
- Состояния: pending_payment, paid, fulfilled, cancelled, expired; счёт в статусе «Готовится»,
  файла ещё нет (скелетон).

### 2.9 `/cabinet/orders` — «Заявки и покупки»

- Список заказов: номер, дата, состав (1–2 позиции + «ещё N»), сумма, плательщик, статус-бейдж,
  документы (иконки). Клик → заказ (2.8).
- Фильтр по статусу. Пусто: «Покупок пока нет» + `{Выбрать пакет}`.
- Верхняя сноска: «Все покупки сохраняются в заявках — их видит поддержка».

### 2.10 `/cabinet/documents` — «Документы»

- Табы: Все · Счета · Акты · Чеки (счётчики).
- Таблица: дата, тип, номер, заказ, сумма, статус, `{Скачать}` (иконка PDF + подпись для
  доступности). Мобильный — карточки.
- Типы: `invoice` «Счёт», `act` «Акт об оказании услуг», `receipt` «Электронный чек».
- Статус `draft` → «Готовится» (без кнопки скачивания), `issued` → доступен,
  `void` → «Аннулирован».
- Архивные счета (до кабинета) переносятся миграцией в `billing_documents` и показываются как
  «Счёт (архив)»; API объединяет неперенесённые.
- Сноска: «Счёт — после оформления заявки, акт и чек — после оплаты. Если чего-то не хватает —
  напишите в поддержку».
- Пусто: «Документов пока нет. Они появятся после первой покупки».
- Скачивание — `document_url` (подписанная ссылка 60 с), ошибка → тост «Ссылка устарела,
  попробуйте снова».

### 2.11 `/cabinet/profile` — «Профиль»

- **Google-аккаунт:** аватар-инициалы, имя, email, «Вход выполнен через Google».
- **Telegram:** @username, дата привязки, `{Перепривязать}` (новый токен); если не привязан —
  баннер и кнопка.
- **Карточка клиента:** имя, телефон (маска), компания, тип (частное/юрлицо); `{Сохранить}`.
- **Реквизиты юрлица:** название, УНП, адрес, банк; показываются, если тип юрлицо/есть заказы.
- **Автопродление:** тумблер «Продлевать пакет автоматически» (по умолчанию включён для новых
  покупок), подпись «За 7 дней до конца периода выставим заявку и счёт»; отключение — сразу,
  если заявка ещё не создана, иначе кнопка «Отменить заявку».
- **Язык:** переключатель RU / EN — меняет интерфейс и сохраняется в карточке (`language`).
- **Email:** адрес из Google, используется для уведомлений; отметить, что письма приходят с mail.ru.
- **Выход:** `{Выйти}` → `signOut` → /support.

## 3. Сценарии

### 3.1 Первая покупка: гость → клиент → оплата

1. Гость на `/support`, нажимает `{Подключить}` у «Стандартного».
2. Товар запоминается (`pendingIntent`: `package:support-standard`), открывается модалка Google.
3. Google OAuth → возврат `/cabinet?add=package:support-standard`.
4. `bootstrap`: карточка найдена по email или создана; ответ `telegram_required`.
5. Редирект на онбординг. Шаг Telegram: клиент открывает бота, жмёт Start; кабинет ловит статус.
6. Анкета: имя/телефон/тип → `{Завершить}`.
7. Кабинет добавляет отложенный товар в корзину и ведёт на `/cabinet/cart`.
8. Выбор плательщика (например, юрлицо) → реквизиты → `{Оформить заявку}`.
9. Экран заказа: «Ожидает оплаты», счёт готовится.
10. Админ в `/admin/support → Заказы`: счёт уже сформирован автоматически; админ проверяет
    документ и подтверждает оплату (ручная загрузка — только если рендер не удался).
11. Клиент: статус «Выполнен», период активен, кредиты начислены, в «Документах» счёт и акт;
    в Telegram — сообщение «Оплата подтверждена, документы в кабинете».

Ветвления:
- Закрыл модалку Google → товар не потерян (можно вернуться и войти позже).
- Закрыл онбординг до Telegram → при следующем входе снова онбординг; покупка недоступна.
- Email Google совпал с существующей карточкой → карточка не дублируется, история видна сразу.
- Telegram уже привязан к другому клиенту с проектом → отказ и контакт поддержки.

### 3.2 Возврат клиента

1. `/cabinet` или шапка сайта → сессия Supabase жива → bootstrap.
2. `complete` → дашборд: пакет, кредиты, задачи, проекты, документы.
3. Если сессия истекла → модалка входа → `/cabinet`.

### 3.3 Докупка кредитов

1. `/cabinet` → `{Докупить кредиты}` (или /support → ползунок/бандл).
2. Товар `topup:1000` в корзине (проект выбирается, если их несколько).
3. Плательщик → заявка → оплата → подтверждение.
4. Кредиты зачисляются на отдельный баланс (`client_credit_topups`) и не сгорают: остаток
   на дашборде вырос, в задачах — прежние списания. Тратятся после кредитов периода и
   сохраняются при смене периода/пакета.

### 3.4 Нет пакета

1. Дашборд: пустое состояние «У вас пока нет пакета» + 4 пакета.
2. `{Выбрать пакет}` → /support#pricing или сразу корзина с выбранным.
3. Дальше — как 3.1 с шага 7.
4. Если у клиента 0 проектов: заказ создаётся без проекта; админ в заявке нажимает
   «Привязать проект» (создаёт карточку проекта), затем «Подтвердить оплату» — период активируется.

### 3.5 Юридическое лицо (счёт → оплата → акт)

1. Корзина → «Юридическое лицо» → реквизиты → `{Оформить}`.
2. Заказ `pending_payment`; статус документа «Счёт готовится».
3. Счёт формируется автоматически: `billing_documents(invoice)` + PDF в Storage.
4. Клиент: `{Скачать счёт}` → оплата по реквизитам.
5. Админ: «Подтвердить оплату» → период активен, акт выпущен.
6. Клиент: «Документы» → счёт + акт; уведомление в Telegram.

### 3.6 Физическое лицо (ссылка → чек)

1. Корзина → «Частное лицо» → `{Оформить}`.
2. Заказ `pending_payment` + `{Перейти к оплате}` (ссылка).
3. Оплата; админ подтверждает (в будущем — вебхук провайдера).
4. Чек (PDF/ссылка провайдера) появляется в «Документах»; уведомление.

### 3.7 Задачи из Telegram

1. Клиент пишет боту, привязанному к кабинету.
2. Агент выполняет в рамках периода; `support_jobs` + списание кредитов.
3. Кабинет «Задачи»: запись, статус, «−20 кредитов»; остаток на дашборде уменьшился.
4. ИИ-ответ в боте и кабинет показывают одинаковый остаток.

### 3.8 Документы

1. `/cabinet/documents` → табы.
2. `{Скачать}` → подписанная ссылка. Нет файла → «Готовится» и подсказка.
3. Ошибка подписи → тост и повтор.

### 3.9 Перепривязка Telegram

1. Профиль → `{Перепривязать}` → новый токен → бот → статус.
2. Если новый Telegram занят другим кабинетом → отказ, старая привязка сохраняется.

### 3.10 Отмена/просрочка заявки

1. `pending_payment` истёк (5 дней) → `expired`, баннер «Заявка просрочена»,
   `{Повторить}` возвращает позиции в корзину.
2. `{Отменить}` до оплаты → `cancelled`; документы не выпускаются; корзина не восстанавливается
   автоматически (кнопка «Повторить»).

---

### 3.11 Автопродление

1. У проекта включён `auto_renew`, до конца периода 7 дней.
2. Job создаёт заявку `kind='renewal'`: счёт генерируется автоматически, письмо и сообщение в бот
   «Продление пакета: заявка ST-…, оплатить до …».
3. Клиент скачивает счёт и оплачивает; админ подтверждает — новый период встаёт в очередь
   со стартом в дату конца текущего.
4. Отключил автопродление до создания заявки — ничего не создаётся; после — заявка отменяется,
   счёт аннулируется.
5. Не оплатил к дате — заявка и период `expired`, баннер «Пакет истёк», письмо; покупка обычным путём.

### 3.12 EN-версия

1. Клиент открывает `/en/cabinet` или переключает язык в шапке — интерфейс на английском,
   данные те же, выбор сохраняется в `clients.language`.
2. Документы (счёт/акт/чек) и юридические тексты — на языке клиента (RU/EN); оферта и акт
   переводятся, письма — на языке клиента.

### 3.13 Email-уведомления

1. Заявка создана → письмо `order_created` со ссылкой на заказ.
2. Счёт готов → письмо `invoice_ready` с кнопкой «Открыть кабинет».
3. Оплата подтверждена → `paid`; документы готовы → `docs_ready`.
4. Ошибка SMTP → повтор до 5 раз; при отсутствии email канал пропускается.

## 5. Админ-сторона (влияет на клиента)

- **`/admin/support → Заказы`:** список (статус, плательщик, сумма, клиент), карточка заказа:
  позиции, реквизиты, документы; действия «Перевыпустить/загрузить счёт» (fallback), «Подтвердить оплату» (активирует период
  и кредиты), «Отменить», «Загрузить документ».
- **`/admin/support → Документы`:** все счета/акты/чеки, фильтры, выпуск/загрузка/аннулирование.
- **Карточка клиента:** блок «Личный кабинет» — Google email, Telegram, дата входа, заказы, документы,
  кнопка «Слить с карточкой…» (при конфликте).
- **Проект:** поля `title`, `domain`, `platform`, `public_url` — то, что видит клиент.
- Подтверждение оплаты идемпотентно; повторный клик ничего не дублирует.
- **Автопродление:** заявки `kind='renewal'` помечены бейджем «автопродление», их можно отменить;
  счёт выпускается автоматически, акт — после подтверждения оплаты.
- **Документы:** счёт/акт/чек рендерятся автоматически; админ видит ошибки рендера и может
  перезапустить или загрузить файл вручную; оферта и политика — ссылки в футере и корзине.

## 6. Крайние случаи

1. **0 проектов:** пакет купить можно (заказ без проекта; админ привязывает проект до
   подтверждения оплаты, иначе `project_required`); докупку тоже можно — кредиты лягут на баланс
   клиента и применятся к любому будущему проекту.
2. **Несколько проектов:** пакет отображается по проектам; корзина требует выбрать проект;
   один заказ = один проект (v1).
3. **Несколько пакетов/периодов:** остаток — сумма активных; истёкшие не показываются как активные.
4. **Лимит исчерпан:** баннер и сообщение бота; новые правки — после докупки/продления.
5. **Период истёк:** дашборд — «Продлить», задачи read-only, покупка доступна.
6. **Email Google ≠ карточка:** поиск по email → если нет, создаётся новая; при привязке Telegram —
   слияние по правилам data-api §7; конфликт — поддержка.
7. **Telegram занят другим клиентом:** отказ без автослияния.
8. **Дубль оплаты/двойной клик:** `idempotency_key`; второй запрос возвращает тот же заказ.
9. **Цена изменилась:** `price_changed`, баннер с новыми ценами, подтверждение.
10. **Нет интернета/ошибка API:** сообщение + повтор; корзина не теряется.
11. **Сессия истекла:** модалка входа, после — возврат на тот же экран.
12. **Документ ещё не готов:** «Готовится», без ложной кнопки скачивания.
13. **Клиент удалён/заблокирован:** кабинет показывает «Аккаунт недоступен, напишите в поддержку».

## 8. Критерии приёмки

**Навигация и доступ**
- [ ] Гость видит `{Личный кабинет}`; после Google — чип кредитов и аватар.
- [ ] Без Telegram любой `/cabinet/*` ведёт на онбординг; покупка заблокирована.
- [ ] 380 px и 1440 px — без горизонтального скролла; фокус и aria-подписи есть.
- [ ] `/en/cabinet/*` работает, язык переключается в шапке и профиле и сохраняется.

**Онбординг**
- [ ] Google-вход создаёт/находит карточку; повторный вход не плодит дубли.
- [ ] Telegram привязывается через `cab_` токен; таймаут и «занят» обработаны.
- [ ] Анкета сохраняется; после «Завершить» — дашборд.

**Дашборд и данные**
- [ ] Пакет и кредиты совпадают с БД: период `credits_limit − credits_used` + баланс докупок.
- [ ] Нет пакета → оффер; истёк/мало кредитов → баннеры.
- [ ] Задачи с кредитами и проекты — реальные, без внутренних полей.

**Корзина и покупка**
- [ ] Кнопки /support добавляют товар; гость проходит Google; счётчик обновляется.
- [ ] Выбор физ/юрлица; валидация УНП; цена пересчитывается на сервере.
- [ ] Checkout создаёт заказ + заявку; повторный клик не дублирует.
- [ ] Ожидающая оплата видна в дашборде и «Заявках».
- [ ] Без принятия оферты оформить заявку нельзя; ссылки на оферту и политику открываются.
- [ ] Чекбокс автопродления сохраняется и меняет флаг `auto_renew`; возврат к ручному режиму работает.

**Документы**
- [ ] Юрлицо: счёт и акт генерируются автоматически, видны и скачиваются; физлицо: чек.
- [ ] Документ появляется без действий админа; ошибка рендера видна админу и повторяется.
- [ ] Чужой документ недоступен (403); ссылка истекает и обновляется.

**Админка**
- [ ] «Подтвердить оплату» активирует период и начисляет кредиты; идемпотентно.
- [ ] Документы выпускаются и появляются у клиента.
